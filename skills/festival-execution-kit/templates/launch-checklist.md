# 上線前檢查表

用法：D-7 開始跑，D-1 前每一項都要有人真的打開頁面或後台確認過再打勾。
每項後面補上 `@負責人 完成日`，不確定是誰就寫 `@[待指派]` 並列進風險。
打不勾的項目不要跳過，寫下卡在哪裡與預計解決日。

## 商品與庫存

- [ ] 所有檔期品項已在後台建檔，用品名搜尋找得到 `@[待指派] <日期>`
- [ ] 每個檔期 SKU 的可售庫存數大於首批預估出貨量（預估值來自自家歷史出貨資料，非外部推估）
- [ ] 組合包／禮盒已完成組裝，或已確認可即時組裝並指定組裝人力與地點
- [ ] 贈品與加購品已入庫，數量與主商品備貨量對得上
- [ ] 缺貨自動下架或改顯示「補貨中」的設定已開啟，並實測過一次
- [ ] 品號／條碼與通路提供的資料一致，已用一筆測試訂單驗證
- [ ] 效期最短的品項確認可撐過檔期與節後長尾

## 頁面與內容

- [ ] 活動頁在手機無痕視窗開得起來，未登入狀態也看得到
- [ ] 手機版逐屏看過：主視覺沒被裁切、按鈕點得到、文字沒被切掉
- [ ] 所有 CTA 逐一點過，每個都連到正確頁面，沒有 404
- [ ] 商品圖與文案的品名、規格、內容物與實際出貨物一致
- [ ] 活動規則明寫期間、參加資格、限購數、不可與哪些優惠並用
- [ ] 已排程的貼文與 EDM 在後台看得到排程時間，時區正確
- [ ] 頁面沒有殘留上一檔期的日期、價格或優惠碼
- [ ] 分享預覽（OG title／縮圖）已設定，實際貼一次連結確認顯示正常

## 價格與優惠機制

- [ ] 每個檔期 SKU 的售價與計畫書／通路 brief 逐筆對過
- [ ] 所有優惠碼已在後台建立，逐一輸入測試並成功折抵
- [ ] 每個優惠碼的使用次數上限、單人限用、有效期間、適用品項四項都檢查過
- [ ] 疊加測試：把可能同時使用的優惠一起套用，確認最終售價不低於毛利底線
- [ ] 滿額門檻與免運門檻的計算方式（含稅前後、是否含運費）已用測試訂單驗證
- [ ] 優惠到期會自動失效，已用測試碼或後台排程確認
- [ ] 錯價／錯碼的處理說法與補償上限已寫好，決定人已指定

## 金流與物流

## D-day 當天監控清單

尖峰時段每小時一輪：

- [ ] 活動頁在手機無痕視窗打得開，結帳流程走得完
- [ ] 主推品項庫存數字，是否接近安全水位
- [ ] 訂單量與時段分佈，與前一日同時段比較
- [ ] 廣告是否還在跑，有無素材被拒或帳戶被限制
- [ ] 客服未回訊息數，以及最常出現的那個問題
- [ ] 社群留言與私訊有無集中出現的抱怨

固定時間點：

- [ ] 開賣後 30 分鐘：確認至少一筆真實訂單成功且出現在報表
- [ ] 中午與晚間尖峰前 30 分鐘：確認庫存與待出貨量
- [ ] 當日最後出貨截止前 2 小時：發出最後提醒
- [ ] 收班前：記下當天數字與異常事件，交給 festival-campaign-review

## 出事時的處理順序

1. **止血**：先讓客人不再受影響——關掉錯誤優惠、下架錯價商品、暫停廣告。先止血，再查原因。
2. **定調**：當日決定人在 `<分鐘>` 內拍板一句對外說法，客服、社群、通路一律用同一句。
3. **通知**：同步進緊急聯絡群組，指定一人對外、一人查原因，其他人不要各自回覆。
4. **補償**：確認受影響名單與補償上限，由 `<決定人>` 核可後統一發布。
5. **修復並驗證**：修好後由最初回報的人重跑一次同樣操作確認，不是工程說好了就算好。
6. **記錄**：寫下時間、影響範圍、處理動作與決策依據，供覆盤使用。

> ⚠️ 順序不能顛倒。先查原因再止血，等於讓錯誤一直發生；先發補償再定調，會出現多套說法。
