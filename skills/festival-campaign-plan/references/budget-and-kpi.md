# 預算與 KPI

**這份檔案不提供任何比例、金額或行業基準值。** 所有參數都必須來自使用者自己的歷史資料，
或標明出處的外部報告。看到「廣告佔 50%」這種沒有出處的分配建議，那是編的，不要用。

---

## 一、預算反推法

憑空分配比例（廣告 50%、促銷 30%、其他 20%）之所以錯，是因為它從預算出發，
而生意是從目標出發的。正確順序是反過來算：目標 → 訂單 → 流量 → 媒體錢 → 其他科目 → 回頭檢查合理性。

### 五步反推

**Step 1 — 定生意目標金額**
這個檔期要做多少營收（或毛利、或新客數）。來源：老闆／通路給的目標，或去年同期實績乘上成長期望。
若目標是毛利或新客數，後面每一步都要換成對應的分母，不要偷換成營收。

**Step 2 — 目標金額 ÷ 預期客單 = 需要的訂單數／來客數**
`預期客單` 一律取自使用者的歷史資料：同一檔期去年的 AOV，或最近三個月同組合的 AOV。
禮盒、組合包會拉高客單，別直接套平日 AOV。

**Step 3 — 訂單數 ÷ 預期轉換率 = 需要的流量／來客**
`預期轉換率` 一律取自使用者自己的後台：分通路、分裝置、分新舊客各算一組，
節慶期間的轉換率與平日不同，要用「去年同檔期」的數字，不是全年平均。

**Step 4 — 流量 × 各通路獲客成本 = 媒體預算**
`獲客成本`（CPC／CPM／CPA）一律取自使用者自己近期的投放帳戶，並按通路分開估。
節慶期間競價會變貴，這件事要在假設裡寫明，但**貴多少不准憑空填一個倍數**，
用去年同期自家帳戶的實際成本變化來推，或保留為待驗證假設。

**Step 5 — 加上非媒體科目，再回頭檢查**
把下方科目清單逐項估出金額後加總，然後檢查：
- 總預算 ÷ 目標營收 = 行銷費用率。這個比率**要跟使用者自己過去的檔期比**，不是跟不存在的行業標準比。
- 若比率明顯高於自家歷史水準，代表目標訂太高或轉換假設太樂觀，回 Step 1 調整，不要硬編。
- 反推出的流量需求若遠超自家歷史最高流量，那是計畫不可行的訊號，不是「加預算就好」。

### 沒有歷史資料怎麼辦

不准猜一個數字填進去。三個合法做法：

1. **設測試期先跑出參數**：在正式檔期前用小預算跑 1-2 週，實測客單、轉換率、獲客成本，
   再用實測值反推正式預算。時程上要把測試期排進 backplan 的「定策略」到「備彈藥」之間。
2. **用可查證的外部來源**，並在計畫書寫出報告名稱、年份、樣本範圍。沒有出處就不算來源。
3. **標成假設往下走**：`[假設] <數字> — 依據：<推論> — 需驗證：<怎麼驗>`，
   並在「待驗證假設清單」列出驗證時間點。整份計畫的假設數量本身就是風險指標。

## 二、預算科目清單

逐項估，別只估媒體。每項附「常被漏掉的地方」。

| 科目 | 常被漏掉的地方 |
|---|---|
| 媒體投放：站內（平台廣告、關鍵字、資源位） | 平台檔期資源位要提早報名，報名費與保底消耗常被當成免費 |
| 媒體投放：站外（聯播網、影音） | 素材尺寸太多份，製作費被算到媒體費裡導致實際觸及不足 |
| 媒體投放：社群 | 檔期競價變貴，用平日 CPM 估會嚴重低估 |
| 媒體投放：搜尋 | 品牌詞被競品咬走的防守預算 |
| 內容與素材製作 | 改版與多語系／多尺寸重製；攝影的道具、場地、模特兒授權期限 |
| 包裝與物料 | 打樣費與運費；印刷起訂量；包材交期比想像長，是時程的硬約束 |
| 贈品與樣品 | 贈品的倉儲與配送成本；備量不足時的緊急補貨溢價 |
| 通路上架費與陳列費 | 堆頭、端架、DM 版位是分開計費；上架截止日決定整條時程 |
| 平台抽成與金流手續費 | 抽成基準是含稅或未稅、含運或不含運；分期手續費由誰吸收 |
| 物流與倉儲 | 尖峰運費調漲、超材／超重、退貨的逆物流成本 |
| KOC／KOL 合作 | 寄樣品的成本與工時；素材二次使用授權；業配需依規定標註 |
| 活動與場地 | 保險、臨時人力、雨備方案、水電與清運 |
| 客服人力 | 檔期加班與外援人力；退換貨處理工時 |
| 備用金 | 完全沒留，一有變數就砍素材或砍投放 |

### 毛利底線檢查（必做）

促銷的風險是營收漲、毛利掉。每個主推品項都要算：

```
促銷後單位貢獻 = 售價 − 變動成本 − 贈品成本 − 平台抽成 − 物流成本
保本銷量       = 檔期固定投入（媒體＋製作＋上架費＋活動）÷ 促銷後單位貢獻
```

- 單位貢獻若是負的，這個機制不能上，再多流量都是在賠錢，不是「衝量攤提」。
- 折扣、滿額贈、加價購、平台券疊加後要**重算一次**最壞情況的單位貢獻（全部優惠同時被用上）。
- 保本銷量要跟自家歷史同檔期銷量比，明顯超出就是計畫不可行。
- 售價、成本、抽成一律取自使用者的報價單與後台，不是估的。

## 三、KPI 樹與量測前置

### 層級關係

- **北極星指標**：這個檔期成功的單一定義（例：檔期毛利、新客數、售罄率）。只能有一個。
- **前導指標**：北極星的組成因子，可在檔期中途調整（流量、轉換率、AOV、加購物車率）。
- **健康指標**：不能為了衝北極星而犧牲的守門線（毛利率、退貨率、履約準時率、客訴量）。

寫法：北極星 = 前導指標的乘積或加總關係，寫得出算式才算 KPI，寫不出來的是願望。
目標值一律由使用者的歷史資料或標明出處的外部報告填入。

### 常用指標定義與算式

| 指標 | 算式 | 資料從哪來 |
|---|---|---|
| ROAS | 廣告帶來營收 ÷ 廣告花費 | 廣告平台 ×（電商後台歸因報表校正） |
| ROI | （帶來毛利 − 總投入）÷ 總投入 | 財務／後台毛利報表＋預算實支表 |
| CPA | 廣告花費 ÷ 轉換數 | 廣告平台，需確認轉換事件定義一致 |
| AOV | 營收 ÷ 訂單數 | 電商後台或 POS |
| UPT | 銷售件數 ÷ 訂單數 | 電商後台或 POS |
| 轉換率 | 訂單數 ÷ 造訪數（實體：成交數 ÷ 進店人次） | GA／後台；實體需人流計數器 |
| 售罄率 | 已售數 ÷ 備貨數 | 庫存系統 |
| 新客佔比 | 新客訂單數 ÷ 總訂單數 | 會員系統，需先定義「新客」判準 |
| 回購率 | 期間內再購人數 ÷ 前期購買人數 | 會員系統，需定義觀察窗口長度 |
| 加購物車率 | 加購物車事件數 ÷ 商品頁瀏覽數 | 電商前端事件追蹤 |

同一指標在廣告平台與後台的數字幾乎不會一致（歸因視窗、去重方式不同）。
計畫書要**先指定哪一份是結案依據**，避免檔後各執一詞。

### 量測前置作業（必須在開賣前完成）

- **UTM 命名規則**：定好 `source / medium / campaign / content` 的寫法並全團隊統一，
  campaign 帶節慶與年份。事後才想補 UTM，資料已經回不來。
- **專屬優惠碼**：每個通路、每個 KOC 一組獨立碼，這是實體與私域少數可靠的歸因手段。
- **LINE 分眾標籤**：發送前先建好標籤與分眾條件，才能分群看成效與後續再行銷。
- **電商後台匯出欄位**：確認能匯出「訂單層級的品項、折扣、優惠碼、新舊客標記」，
  只有匯總報表就算不出 AOV 與新客佔比。
- **實體通路 POS 對帳與歸因限制**：POS 通常只到日、店、SKU，看不到廣告觸點。
  能做的是活動店／對照店比較與優惠碼回收，這種比較會受天氣、店點差異干擾，結論要保守。
- **⚠️ 做不到歸因的指標就不要列進 KPI。** 列了量不到，檔後只能靠感覺爭論。
  真的重要卻量不到，就先把量測建起來，寫進下一檔的前置作業，交由 festival-campaign-review 追。
